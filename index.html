Case 01 / 04Server crash

Server crashed for hours when high traffic hit a 1 Million URL directory site

01
SITUATION
Every time search engine bots crawled the site for indexing, it went down with server timeout errors, often for several hours at a time. This kept happening, so the site was unreliable for visitors and was failing the crawls it needed to get indexed.
02
WHAT I FOUND
The site had over 1 million URLs, and its custom-built sitemap was regenerated from scratch on every request because an object cache trigger wasn’t working. The PHP-FPM timeout was set to 900 seconds, so each clogged sitemap request held a PHP worker for up to 15 minutes. A few bot hits used up every worker, and the whole server stopped responding.
03
WHAT I DID
I debugged at the server level over the shell. I traced when the crashes happened, which requests triggered them and where in the code the load came from. Then I fixed the object cache trigger and rebuilt the sitemap generation. Now it builds once, and after that it only adds new entries when new content is published.
RESULT
The sitemap builds once in about 30 seconds and then updates incrementally as new content is added. The site went from hours of downtime on every crawl to zero server errors since the fix.
● BEFORE Hours of downtime · PHP workers stuck for 900s
1 Crash pattern traced over SSH
2 Bot hits matched to sitemap rebuilds
3 Object cache trigger fixed
4 Sitemap rebuilt to generate once and update incrementally
● AFTER 30s one-time build · Zero server errors
Case 02 / 04Site down

WooCommerce store went to a white screen overnight

01
SITUATION
Customers saw a blank white page and the owner couldn't log in to wp-admin. Every hour down meant lost orders.
02
WHAT I FOUND
The host had silently upgraded PHP to 8.1. An old, abandoned slider plugin used a function removed in PHP 8, and the fatal error took the whole site down.
03
WHAT I DID
Took a backup, disabled the plugin over SSH to bring the site back, then replaced it with a maintained alternative on staging and tested checkout before going live.
RESULT
Store back online the same day, and the rest of the site checked for PHP 8 issues so it doesn't happen again.
● BEFORE White screen · wp-admin locked
1 Backup taken
2 Broken plugin disabled over SSH
3 Replacement tested on staging
4 Checkout verified live
● AFTER Online same day · PHP 8 ready
Case 03 / 04Hacked / malware

Visitors from Google were redirected to spam sites

01
SITUATION
The owner's own visits looked normal, but customers arriving from Google on mobile were sent to spam pages. Google had started showing a warning.
02
WHAT I FOUND
Injected JavaScript in the theme, a PHP backdoor hidden in the uploads folder, and a fake admin account. The way in was an outdated plugin with a known upload vulnerability.
03
WHAT I DID
Backed up, removed the malware and backdoor, replaced WordPress core files, deleted the rogue admin, reset passwords and keys, blocked PHP in uploads, updated everything, and requested a Google review.
RESULT
Site clean, Google warning removed after review, and the hole they used is closed.
● BEFORE Spam redirects · Google warning
1 Backup taken
2 Malware and backdoor removed
3 Core files, passwords and keys replaced
4 Google review requested
● AFTER Clean · warning removed
Case 04 / 04WooCommerce build

Smarter checkout for a cash-on-delivery store

01
SITUATION
A local store selling on cash-on-delivery kept getting orders with wrong or fake phone numbers, and delivery was charged the same inside and outside Dhaka.
02
WHAT I FOUND
Checkout accepted any text as a phone number, and the existing plugins couldn't set delivery charges by area without adding more bloat.
03
WHAT I DID
Built a small custom plugin: phone number validation at checkout and area-based delivery charges. Tested on staging, written to survive theme and plugin updates.
RESULT
Fewer undeliverable orders, and customers are charged the right delivery fee automatically.
● BEFORE Fake numbers · one flat delivery fee
1 Checkout rules mapped
2 Custom plugin built
3 Tested on staging
4 Live and update-safe
● AFTER Valid numbers · fee by area

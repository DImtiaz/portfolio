Case 01Site down

WooCommerce store went to a white screen overnight

$ tail wp-content/debug.log
PHP Fatal error: Uncaught Error:
Call to undefined function
create_function() in
/plugins/legacy-slider/init.php:42
# host upgraded PHP 7.4 → 8.1
✓ plugin disabled over SSH · site up
Situation
Customers saw a blank white page and the owner couldn't log in to wp-admin. Every hour down meant lost orders.
What I found
The host had silently upgraded PHP to 8.1. An old, abandoned slider plugin used a function removed in PHP 8, and the fatal error took the whole site down.
What I did
Took a backup, disabled the plugin over SSH to bring the site back, then replaced it with a maintained alternative on staging and tested checkout before going live.
Result
Store back online the same day, and the rest of the site checked for PHP 8 issues so it doesn't happen again.
Case 02Hacked / malware

Visitors from Google were redirected to spam sites

$ find wp-content/uploads -name "*.php"
uploads/2024/03/cache-img.php
$ head -c 60 cache-img.php
<?php @eval(base64_decode($_POST[...
# backdoor + rogue admin user
✓ removed · entry point closed
Situation
The owner's own visits looked normal, but customers arriving from Google on mobile were sent to spam pages. Google had started showing a warning.
What I found
Injected JavaScript in the theme, a PHP backdoor hidden in the uploads folder, and a fake admin account. The way in was an outdated plugin with a known upload vulnerability.
What I did
Backed up, removed the malware and backdoor, replaced WordPress core files, deleted the rogue admin, reset passwords and keys, blocked PHP in uploads, updated everything, and requested a Google review.
Result
Site clean, Google warning removed after review, and the hole they used is closed.
Case 03WooCommerce build

Smarter checkout for a cash-on-delivery store

// custom plugin — survives updates
add_action( 'woocommerce_after_checkout_validation',
  'bd_validate_phone', 10, 2 );

if ( ! preg_match( '/^01[3-9]\d{8}$/', $phone ) ) {
  $errors->add( 'phone',
    'Enter a valid mobile number.' );
}
Situation
A local store selling on cash-on-delivery kept getting orders with wrong or fake phone numbers, and delivery was charged the same inside and outside Dhaka.
What I found
Checkout accepted any text as a phone number, and the existing plugins couldn't set delivery charges by area without adding more bloat.
What I did
Built a small custom plugin: phone number validation at checkout and area-based delivery charges. Tested on staging, written to survive theme and plugin updates.
Result
Fewer undeliverable orders, and customers are charged the right delivery fee automatically.
